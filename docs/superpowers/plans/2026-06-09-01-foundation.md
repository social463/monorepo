# Legends — Plano 1: Fundação do Monorepo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Montar o esqueleto do monorepo (pnpm workspaces) com backend Fastify, frontend Vite/React, pacote de tipos compartilhado, Postgres via Docker, schema Prisma completo do MVP e infraestrutura de testes — tudo rodando e testável.

**Architecture:** Monorepo pnpm com `apps/api` (Fastify + Prisma + Postgres, ESM/TypeScript), `apps/web` (Vite + React + TS + Tailwind com tema "Destaque") e `packages/shared` (enums, constantes e schemas Zod). O Prisma define todas as entidades do MVP de uma vez para que os planos seguintes (auth, votação, ranking, selos) construam apenas regras de negócio sobre um modelo de dados estável. Testes com Vitest em ambos os apps.

**Tech Stack:** pnpm, TypeScript, Fastify 4, Prisma 5 + PostgreSQL 16, JWT (`@fastify/jwt`), bcryptjs, Vite 5 + React 18, Tailwind 3, Vitest, Docker Compose.

enum UserRole {

  ADMIN

enum BadgeKind {
  MONTHLY_GOLD
  MONTHLY_SILVER
  MONTHLY_BRONZE
  CATEGORY
  RECURRENCE
  IMPACT

model User {
  id           String   @id @default(cuid())
  email        String   @unique
  passwordHash String
  name         String
  position     String?
  squad        String?
  photoUrl     String?
  role         UserRole @default(DEV)
  active       Boolean  @default(true)
  joinedAt     DateTime @default(now())

  votesReceived Vote[]                @relation("VotesReceived")

model Category {
  id          String   @id @default(cuid())
  name        String
  slug        String   @unique
  description String?
  active      Boolean  @default(true)
  isSpecial   Boolean  @default(false)
  createdAt   DateTime @default(now())

  id        String             @id @default(cuid())
  monthRef  String             @unique // formato "2026-06"

  endsAt    DateTime
  status    VotingPeriodStatus @default(OPEN)
  createdAt DateTime           @default(now())

  votes    Vote[]
  rankings MonthlyRankingEntry[]

model Vote {
  id            String   @id @default(cuid())
  voterId       String
  votedId       String
  categoryId    String
  periodId      String
  justification String
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  voter    User         @relation("VotesGiven", fields: [voterId], references: [id])
  voted    User         @relation("VotesReceived", fields: [votedId], references: [id])
  category Category     @relation(fields: [categoryId], references: [id])
  period   VotingPeriod @relation(fields: [periodId], references: [id])

  @@unique([voterId, votedId, categoryId, periodId], name: "one_vote_per_pair_category_period")

  @@index([votedId])

model Badge {

  description String

```ts
import { PrismaClient, type BadgeKind } from "@prisma/client";
import bcrypt from "bcryptjs";
import { DEFAULT_CATEGORIES } from "@legends/shared";

const prisma = new PrismaClient();

async function main() {
  // 1) Categorias (PRD §8)
  for (const c of DEFAULT_CATEGORIES) {
    await prisma.category.upsert({
      where: { slug: c.slug },
      update: { name: c.name, description: c.description },
      create: {
        name: c.name,
        slug: c.slug,
        description: c.description,
        isSpecial: c.isSpecial ?? false,
      },
    });
  }

  // 2) Selos mensais básicos (PRD §13)
  const badges: {
    slug: string;
    name: string;
    description: string;
    kind: BadgeKind;
    iconKey: string;
  }[] = [
    {
      slug: "monthly-gold",
      name: "Ouro",
      description: "1º lugar do ranking do mês",
      kind: "MONTHLY_GOLD",
      iconKey: "gold",
    },
    {
      slug: "monthly-silver",
      name: "Prata",
      description: "2º lugar do ranking do mês",
      kind: "MONTHLY_SILVER",
      iconKey: "silver",
    },
    {
      slug: "monthly-bronze",
      name: "Bronze",
      description: "3º lugar do ranking do mês",
      kind: "MONTHLY_BRONZE",
      iconKey: "bronze",
    },
  ];
  for (const b of badges) {
    await prisma.badge.upsert({
      where: { slug: b.slug },
      update: {
        name: b.name,
        description: b.description,
        kind: b.kind,
        iconKey: b.iconKey,
      },
      create: b,
    });
  }

  // 3) Usuários de exemplo (senha padrão: changeme123)
  const passwordHash = await bcrypt.hash("changeme123", 10);

  await prisma.user.upsert({
    where: { email: "admin@empresa.com" },
    update: {},
    create: {
      email: "admin@empresa.com",
      name: "Admin",
      passwordHash,
      role: "ADMIN",
      position: "Plataforma",
      squad: "Core",
    },
  });

  const devs = [
    {
      email: "ana@empresa.com",
      name: "Ana Souza",
      position: "Backend",
      squad: "Pagamentos",
    },
    {
      email: "bruno@empresa.com",
      name: "Bruno Lima",
      position: "Frontend",
      squad: "Growth",
    },
    {
      email: "carla@empresa.com",
      name: "Carla Dias",
      position: "Fullstack",
      squad: "Core",
    },
    {
      email: "diego@empresa.com",
      name: "Diego Reis",
      position: "SRE",
      squad: "Plataforma",
    },
  ];
  for (const d of devs) {
    await prisma.user.upsert({
      where: { email: d.email },
      update: {},
      create: { ...d, passwordHash, role: "DEV" },
    });
  }

  // 4) Período de votação aberto para o mês corrente
  const now = new Date();
  const monthRef = `${now.getFullYear()}-${String(now.getMonth() + 1).padStart(2, "0")}`;
  const startsAt = new Date(now.getFullYear(), now.getMonth(), 1);
  const endsAt = new Date(now.getFullYear(), now.getMonth() + 1, 0, 23, 59, 59);
  await prisma.votingPeriod.upsert({
    where: { monthRef },
    update: {},
    create: { monthRef, startsAt, endsAt, status: "OPEN" },
  });

  console.log("Seed concluído.");
}

main()
  .then(async () => {
    await prisma.$disconnect();
  })
  .catch(async (err) => {
    console.error(err);
    await prisma.$disconnect();
    process.exit(1);
  });
```

## Roadmap dos próximos planos (MVP — PRD Fase 1)

Cada plano é independente e entrega software funcionando sobre esta fundação:

- **Plano 2 — Auth & Usuários:** registro/login com bcrypt + JWT (`@fastify/jwt`), middleware de autenticação, `GET /me`, listagem de devs elegíveis (`GET /users`), schemas Zod de auth no `shared`. Frontend: tela de Login + contexto de sessão.
- **Plano 3 — Votação:** `POST /votes` com regras (justificativa obrigatória, não votar em si mesmo, período aberto, unicidade votante×votado×categoria×período), `GET /categories`, histórico de votos. Frontend: fluxo de votar (selecionar colega → categoria → justificativa → confirmar).
- **Plano 4 — Ranking & Selos:** cálculo do ranking mensal com regras de desempate (PRD §12), top 3, fechamento de período gerando `MonthlyRankingEntry` + atribuição de selos ouro/prata/bronze. Frontend: Dashboard com top 3 e selos do mês.
- **Plano 5 — Histórico & Perfil:** histórico por mês/pessoa/categoria, perfil do colaborador (acumulado de votos, categorias recorrentes, selos, justificativas). Frontend: páginas de Perfil e Histórico.
- **Plano 6 — Admin:** CRUD de categorias, definição de período de votação e critérios de elegibilidade/desempate, moderação básica. Frontend: painel administrativo.
